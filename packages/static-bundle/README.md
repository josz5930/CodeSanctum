# Static Bundle Package

Home for future Signed Static Bundle and Generated Static Portal tooling.

Static bundle generation must be a verifiable projection over retained protocol artifacts and review events. Offline portal output must preserve scope, receipt chain, limitations, and artifact references.

Story 3.5 adds `projectStaticBundleOutcomeSections`, a minimal dependency-free projection scaffold for protocol-backed customer-facing finding records. It extracts accepted-risk and false-positive sections only from valid customer-facing/exportable records, carries record refs, actor category, evidence basis, evidence refs, rationale/sign-off copy, and limitations, and fails closed (`null`) when outcome sections are absent, hidden, or excluded from evidence-consumer export. This is not full Attestation generation or a hosted/static portal renderer.

Story 4.1 adds `projectStaticBundleVerificationScope`, a minimal pure projection over a valid customer-facing verification-pass scope artifact/read model. It carries the verification pass ref, deadline, selected finding refs/statuses, included script slots, additional script candidates marked pricing TBD, and claim-safe limitations while failing closed for malformed, internal-only, hidden, or outcome-like scope input.

Story 4.4 adds `projectStaticBundleVerificationAddendum`, a standalone pure projection over a valid customer-facing verification addendum. It preserves the original review/scope refs and selected commit, canonical per-finding outcomes, reviewer/evidence references, retained and deleted evidence states, limitations, finalization, and print-safe relative history/artifact links. Pending/customer-side-validation findings cannot project as finalized, duplicate or overlapping retained/deleted evidence fails closed, and deleted evidence is never reconstructed.

## Epic 5 signed package and offline portal

- `prepareSignedStaticBundle` creates a deterministic content-addressed manifest over Attestation, Evidence Bundle representation, Vendor Receipt, complete portal assets, and export-approved retained files. `static_bundle_id` is a stable `static_bundle:*` identity across manifest versions; `static_bundle_manifest_id` is the SHA-256 identity of each version. Generation requires every deletion reference to resolve to a deletion-evidence record and rejects any included artifact listed as deleted.
- `canonicalizeStaticBundleJson` is a dependency-free deterministic helper; `sha256Text` is a deterministic SHA-256 helper backed by `node:crypto`. `createStaticBundleSigningRequest` builds the `ml_dsa_65` signing request an external signer needs; this workspace never loads a key and never signs. `prepareSignedStaticBundle`/`completeSignedStaticBundle` (and the finalization pair) split generation around that external signing step, and the resulting signature bytes are trusted only through a caller-supplied `SignatureVerificationOutcome`.
- `prepareFinalizedStaticBundle`/`completeFinalizedStaticBundle` require customer authority and visible-context confirmation. They create and bind a signature over a higher manifest version with `supersedes_static_bundle_manifest_id`; it never mutates generated bytes. Generated and finalized helpers emit canonical content-addressed `review-event` records with derived idempotency, exact singleton artifact refs, sequence metadata, and no source payload. `projectFinalizedStaticBundle` exposes customer control after export.
- `generateStaticPortal` returns self-contained `portal/index.html`, `portal/styles.css`, and `portal/portal.js`. Fixed overview/scope/receipt/methods/findings/validation-remediation/limitations/appendices navigation, within-package search, copy controls, print preservation, phone summaries, reduced motion, and active navigation work without a hosted session, remote asset, live API, or analytics.
- `projectSupportingEvidenceMapping` emits only approved/versioned SOC 2 supporting-evidence, generic technology-risk, and customer-security-review projections with relative print-safe links and explicit evidence-consumer decision authority. Unapproved regional claims and internal feedback are omitted.

Generation fails closed for missing required identities/files, invalid or mismatched digests, unsafe relative paths, incomplete portal files, unapproved exports, or deleted content reintroduction. Source-derived bytes are never reconstructed. Internal pilot metrics/feedback keys are rejected from mapping and portal inputs and therefore cannot enter HTML, search, print, manifest files, or customer projections.
